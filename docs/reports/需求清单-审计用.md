## A. 功能需求（用户明确提出）

| A2 | 战团银行归在"银行"，不单独分类 | 不存储、不扫描、不单独成行；`includeAccountBank=true` 并入"银" |

| A5 | 不要太复杂、不需要导入 | 5 文件、零第三方库、无导入/迁移；SavedVariables 用新名 `SL2_DB` |

| A11 | 数量块上下各一空白行 | `AddLine(" ")`，仅有数据时 |
| A12 | 当前角色名下红色下划线 | 1px 纹理锚定该行；非物品提示框/OnHide 时隐藏 |
| A13 | 数量块放提示框"尽量前面"→修正为**原生说明之后** | 官方 `AddTooltipPreCall`+`AddLinePostCall`（全部行类型，判"原生最后一行"）；`tooltipPostCall` 兜底末尾插入 |

## B. 质量要求（会话中形成的事实标准）

- 三道关卡必须全绿：`lua-check.js`（语法）、`api-audit.js`（弃用 API 0 ERROR）、`simple-smoke.js`（无头行为测试，当前 89 用例）
- 新缺陷必须钉进回归测试（含"反例"验证防假绿）
- 与 EllesmereUI 等皮肤/提示框插件共存；不替换原生方法（仅 hooksecurefunc/HookScript）
- CHANGELOG/README（中英）随行为变更同步；版本号递增

## D. 已知历史缺陷（均已修复+回归测试，审计不必重报，但可复查修复是否完整）

1. 勾选框无文字（模板无文本元素 + SetText 造无锚点 FontString）
2. 悬停反白背景（DefaultTooltipMixin:OnEnter → HoverBackground:Show）
3. 字号只对第一行生效（AddLine 返回值不可靠）
4. 谁都没有的物品渲染 `0` 行（Lua 0 为真值）
5. 全角括号在英文下挤在一起
6. 测试装置：stubTable 引用不存在的 Ls、GetStringWidth 曾是返回 0 的桩且被重复定义覆盖

## E. 审计员需要特别求证的疑点（Lead 预判，需要确认或证伪）

- E1 悬停状态残留：`pending[tooltip]` 以 tooltip 为键、只在 Item 型 pre-call 里重置。
  若一次物品提示框流程中断（既没走到行回调插入、也没走到 post-call 兜底），残留的
  `itemID + lineCount` 是否可能让**下一次同帧的单位提示框**在 `lineIndex == lineCount`
  的巧合下插入数量块？（OnAnyLine 注册在全部行类型上，单位提示框也会触发）
- E2 `IsLastNativeLine` 的 `lineIndex == p.lineCount` 判据在 append 模式（info.append）
  下是否会把"追加段"误判为原生最后一行？
- E3 `AlignDetailColumn` 用各行自己的字体测量，但全局字号在 `FinalizeBlock` 里应用——
  顺序是否在所有路径下都保证"先定字号后测量"？ItemRefTooltip 路径呢？
- E4 `Scan.lua` 只在 `BANKFRAME_OPENED` 记录银行：材料银行页（若独立容器）是否漏记？
  银行包栏 BankBag(-4) 是否计入？
- E5 战团并入"银"依赖 `includeAccountBank` 第 5 参——12.1.0 客户端是否真的支持该参数
  （live 源码级证据）？若不支持，"银"会少算战团部分。
- E6 语言切换写 `SL2_DB.options.locale` 但不 Fire CONFIG_CHANGED——tooltip 缓存里
  是否有语言相关内容需要失效？（rows 只存数字与名字，初步判断无，需确认）
