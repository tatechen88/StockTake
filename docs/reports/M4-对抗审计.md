## 方向 1 · taint / 战斗安全 —— 结论：未发现缺陷（确证）

审查 `Tooltip.lua`、`UI/Options.lua`、`UI/Widgets.lua`（对 Widgets/Options 用 grep 覆盖全部 `SetPoint/Show/Hide/SetScale/hooksecurefunc/HookScript/SetScript/IsForbidden/InCombatLockdown` 命中点逐一核对）。

1. **无原生方法替换**：全文仅有的钩子均为安全写法——
   - `Tooltip.lua:472` `hooksecurefunc(tooltip, "Show", ShowPostHook)`
   - `Tooltip.lua:647` `hooksecurefunc(ItemRefTooltip, "SetHyperlink", …)`
   - `Tooltip.lua:655` `ItemRefTooltip:HookScript("OnShow", …)`（HookScript 追加式，不替换）
   - `Widgets.lua:653-668` 滑条双击恢复默认明确用 `HookScript` 而非替换原生 `OnMouseDown`。
   - **0 处直接覆盖原生函数/脚本。**
2. **受保护 frame 的 SetPoint/Show/Hide/SetScale**：`GameTooltip`/`ItemRefTooltip` **均非受保护 frame**。`Tooltip.lua` 战斗中可能触发的只有 `ApplyFrameOptions`（`:490-511` 的 SetScale/SetPadding/SetMinimumWidth）、`ShowPostHook`（`:463` 二次 `tooltip:Show()`）、`RenderItemTooltip`（`:619-621` `tooltip:Show()`），全部作用于非保护 tooltip，**不产生 taint，也不触碰任何 protected frame**。Options/Widgets 的 SetPoint/Show/Hide 只作用于自建 Frame，且由用户主动打开面板时发生。
3. **GameTooltip 污染防护**：`Tooltip.lua:528` `if tooltip:IsForbidden() then return end`；`:536` 只处理 `GameTooltip`/`ItemRefTooltip`。`globalMode`（默认 false）遍历全 tooltip FontString 改字体是**兼容性风险而非 taint**（FontString 非受保护对象），UI 已加警告。

> 附注（观察项，非缺陷）：`ShowPostHook` 在 `need==true` 时二次 `tooltip:Show()`，会连带触发**其它插件挂在 Show 上的 hook 再次运行**（`reapplying` 只挡自身递归）。轻微重入副作用，不构成 taint。

## 方向 2 · 反覆盖机制是否误伤他人行 / 内存

核心逻辑 `Tooltip.lua:349-450`：`rendered[tooltip]`（`__mode="k"` 弱键）+ 每条 `rec={fs,text,role,path,size,flags}`，`ReapplyOwnLines` 仅当 `GetText()==rec.text` 且字体被改才回写。

### F2.1 文本指纹碰撞（误伤他人行）—— 理论成立、概率极低（P2，需实测）

- 反例需同时满足：另一插件在被复用的同一 FontString 上写出**逐字节相同**的 StackLedger 行（相同计数 + 相同 `|cFF…` 色码 + 相同模板字面量），且它随后改了字体、StackLedger 的 Show 后置钩子又命中。仅当用户同时装「输出格式与 StackLedger 完全一致」的第二个计数插件才可能。`rec.text` 含自身色码，碰撞面极小。
- **颜色码差异 / 文本被截断**：这两种都会使 `GetText()!=rec.text` → 记录被**丢弃**（`:442`「文本已变…永不再碰」），方向是**安全侧**（宁可不回写、不误伤）。**不是缺陷**，符合 §15.5 判决。
- 修法（可选）：`rec` 再记录一个「行内自身数字指纹」（如 `char` 名 + total），比纯文本更稳；但收益有限。

### F2.2 `queryCache` 无上限且非弱引用（P2，确证）

- `Tooltip.lua:201` `local queryCache={}` 以 itemID 为键缓存整份 `Counter:Query` 结果，只在 `SL_DB_UPDATED`/`SL_CONFIG_CHANGED` 整清（`:202-208`/`:673-676`）。两次失效事件之间随「悬停过的不同 itemID 数」单调增长，**无容量上限/无 LRU/无弱引用**。极值可累积数万条目。
- 修法：`ClearQueryCache` 加阈值（如 >2000 整体清空）或改 `__mode="v"` 弱值表；另 `Counter.lua:11 cache` 是等价第二层缓存，可合并。

> 内存澄清（与任务假设相反，不列缺陷）：`rendered`/`shownHooked`/`refPending` 均为弱键表，且 `GameTooltip`/`ItemRefTooltip` 条目是**每次渲染整体替换**而非追加——**「记录表随悬停无限增长」不成立**。

## 方向 4 · 性能与内存 —— 结论：1 P1 + 1 P2 + 1 观察项

### F4.1 `SL_DB.global.items` 无上限增长、零清理路径（P1，确证）

- `Database.lua:51-53` 建表；`:246-268` `SetMeta` 对**每个见过的 itemID** 写 `{name,icon,quality}`。全库唯一清理是 `PruneOld`（`:378-395`，只删 chars）与 `ForgetChar`（只删 chars）。**无任何路径回收 `global.items`**。
- 该表是 SavedVariable，**跨会话永久累积**，存档文件单调膨胀（受物品目录量级限制、单条很小，故 P1 非 P0，但确属「明显缺陷」）。契约有 `cleanupDays` 服务角色、物品元数据不对称地无回收。
- 修法：`PruneOld` 追加反向标记——遍历 `chars[*].{bags,equip,bank,reagent}` 收集仍被引用的 itemID，删除 `global.items` 中未被引用条目；或数据页加「重建物品元数据」按钮。

### F4.2 装备图标取数用错 API 返回类型（P2，确证，被 fallback 掩盖）

- `Scanner_Equip.lua:70-74`：
  ```lua
  local okIcon, texture = pcall(GetInventoryItemTexture, "player", slot)
  if okIcon then icon = tonumber(texture) end
  ```
  `GetInventoryItemTexture` 返回**纹理路径字符串**（`Interface\Icons\…`），非 fileID；`tonumber(texture)` 恒 nil，`icon` 恒 nil，每次都落到 `:83` 的 `icon or ItemIcon(itemID)`（`C_Item.GetItemInfoInstant`，`:39-49`）兜底——meta.icon 最终仍正确，但这段是**死代码 + 语义错误**。
- 修法：删 `GetInventoryItemTexture` 分支，直接 `icon = ItemIcon(itemID)`（契约 §14.2.6 已明确装备图标来源）；若要纹理 fileID 应改 `GetInventoryItemInfo("player", slot)` 第 5 返回值。

### F4.3 全量扫描最坏情况与缓存（观察项，非缺陷）

- 最坏一次 `SL:ScanAll()`：背包 0-5（~238 槽）+ 装备 19 + 角色银行（6+1 页 + 材料区 ~600 槽）+ 战团（~5 页 ~490 槽）≈ **1300+ 槽**，每槽一次 pcall `GetContainerItemInfo`；BAG_UPDATE 走 0.2s Debounce 合并，量级可接受，属契约 §4「全量重扫」既定设计。
- 「每次悬停 O(角色数×分类) 且无缓存」**不成立**：存在两层缓存 `Counter.lua:11 cache` + `Tooltip.lua:201 queryCache`，均按 itemID，重复悬停 O(1)。代价是 `SL_DB_UPDATED` 每次整清 → 频繁存取时首悬停重算 O(角色数×4)，角色数通常个位到几十，开销很小。**不列缺陷。**
- `bank:ScanAll` 每次（含 BAG_UPDATE 触发的 debounce）都 `RefreshTabs()`/`DetectReagentTab()`，略浪费，可优化，非缺陷。

### itemID 为 nil 的缓存污染 —— 未发现（确证）

- `Scanner.ScanContainers`（`Scanner_Bags.lua:64-79`）`if itemID then` 才写 counts；`Counter:Query`（`Counter.lua:44-47`）对 nil 返回 `EmptyResult()` 且**不缓存**；`Data:SetMeta`（`:248-251`）nil 直接 return；`Tooltip.Query` 仅在 `ResolveItemID` 非空后调用（`Tooltip.lua:540-541`）。**nil 不进入任何缓存键。**

   - `Options.lua:641` `L("OPT_TEMPLATE_CUSTOM")` → enUS:77 已定义；
   - `Options.lua:1244` `L("MSG_UNKNOWN_CMD")` → enUS:182 已定义。
3. `LF`（`Options.lua:54-63`）与 `L:Format`（`enUS.lua:26-32`）对「模板缺参/占位符残留」有显式回落，不会把 `%d/%s` 或键名露到界面。
4. zhCN 门控（`zhCN.lua:17`）正确；zhCN 未覆盖键仍落到 enUS 基表**真实条目**（非 metatable），显示英文而非键名。

### X-1【确证·P1】`tooltipPadding` / `minWidth` 回退到中性值不生效（需 /reload 才复原）

- 位置：`Tooltip.lua:504-510`。`tooltipScale` 回退已在 §15.1 用 `SL.Tooltip._appliedScale` 修好；但 `SetPadding`（`padding>=0` 才调）与 `SetMinimumWidth`（`minWidth>0` 才调）**没有同类追踪**。用户把 padding 8→-1、minWidth 200→0 时，代码不再调用任何 API，帧上残留上一次值直到 /reload。
