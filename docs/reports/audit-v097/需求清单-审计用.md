## 1. 本次审计范围：0.9.7 改了什么

背景：0.9.4 曾用 `C_Item.GetEquippedCount` 减"已装备数"，但该 API 在 12.1 **不存在**
（官方 apidoc 12.1.0/12.0.7/11.2.7 零命中 + 社区 wiki 无页面，双源确认），防御式写法使其
静默失效三个版本。0.9.7 三个提交依次做了：

1. **`6ceee77`**：改用 `GetInventoryItemID("player", slot)` 遍历装备槽(INVSLOT 1..19)自数；
   新增 `PLAYER_EQUIPMENT_CHANGED` 监听全量重建；删除 `Enum.BagIndex.BankBag` 死代码；
   测试装置删除两个"真机不存在"的假设施（GetEquippedCount 桩、BagIndex.BankBag 假成员）。
2. **`9a8f6a3`**：修上面带出的回归——减法生效后"只戴着、没有备件"的物品 `背0 银0`，
   被"一件都没有就不占位"挡掉，整块消失。改为**装备单独成列**：行出现条件改为
   `背+银+装备>0`，总数含装备，明细列追加 `· 装备 N`（仅 >0 时）。
3. **`abb9400`**：清理调试残留（删 `Tooltip:ClearCache`/`Tooltip:CacheSize`/`SL.Tooltip`
   空命名空间）；两条缓存测试从"读内部计数器"改为**行为断言**。

## 3. 需求/不变量清单（A1–A12，逐条核对）

- **A1** 「背」= `GetItemCount(id)` − 装备数（装备数 = 该 itemID 占据的装备槽件数，每槽 +1）
- **A2** 「银」= `GetItemCount(id, true,false,true,true)` − `GetItemCount(id)`（含战团银行）
- **A3** 「装备」= 装备槽件数；**每槽 +1**（装备槽无堆叠语义）
- **A4** 当前角色行 total = 背+银+装备；**其他角色行 total = 其记录的背+银**（他们的装备不可知）
- **A5** 行出现条件：当前角色 `背+银+装备>0`；其他角色 `背+银>0`；谁都没有 → 整块不出现
- **A6** 合计 = Σ各行 total
- **A7** 装备表生命周期：`PLAYER_ENTERING_WORLD` 建表、`PLAYER_EQUIPMENT_CHANGED` 全量重建、
  **不入存档**（纯内存）；两个依赖缺失时兜底（常量→1..19；API 缺→全 0 = 旧行为，不 crash）
- **A8** 缓存失效：`DATA_CHANGED` / `EQUIPMENT_CHANGED` / `CONFIG_CHANGED` 三者都清缓存
  并重放已显示的提示框（0.05s 去抖）
- **A9** 明细列显示规则：`背` 恒显示；`银`、`装备` 仅 >0 时追加（`· 银 N`、`· 装备 N`）
- **A10** 无调试接口：不再存在 `Tooltip:CacheSize` / `Tooltip:ClearCache` / `SL.Tooltip`
- **A11** 装置保真：`tools/wow-mock.js` 不提供真机不存在的 API/枚举成员；
  `Enum.BagIndex` 与 apidoc 逐字一致
- **A12** 三语同步：`EQUIPPED` 词条三表齐；README FAQ 三份都有"身上的装备算在哪"；
  CHANGELOG 三份 0.9.7 条目语义一致

## 4. 疑点清单（E1–E10，请逐条给出裁决）

裁决格式：`确认（是真问题）/ 证伪（不是问题）/ 无法确定（说明需要什么验证）`。

- **E1** 合计的不对称：当前角色含装备、其他角色不含（无法知道其装备）。文档是否说清了这一点？
  「其他角色登录时顺便记录其装备」是否应列为后续改进？
- **E2** 衬衫(槽4)/战袍(槽19)：若 `GetItemCount` **不**统计这两类装饰位，而装备表把它们数进去了，
  「背」就会少算。评估风险与可行的验证方法（F1 的实测并未覆盖衬衫/战袍）。
- **E3** 换装时序：`PLAYER_EQUIPMENT_CHANGED` 到达时，`GetItemCount` 是否已反映新状态？
  若否，重放可能短暂显示旧数字（0.05s 去抖是否足以掩盖）。
- **E4** `local equipped = SL.GetEquippedCount and SL:GetEquippedCount(itemID) or 0`
  的布尔语义：`GetEquippedCount` 返回 0 时（Lua 中 0 为真）结果是否仍正确？
- **E5** `CurrentCounts` 改为返回 3 值后，代码里是否还有按 2 值接收的旧写法残留？
- **E6** 装备列让右列（明细）变长：`AnchorDetailColumn` 的固定像素列与提示框宽度计算是否仍正确？
  右列过长时会不会溢出/换行/被裁剪？
- **E7** 测试 12h 用 `self.indexOf(': 1')` 断言总数——是否可能被其他内容（如合计行）误匹配而恒真？
- **E8** 装置 `setEquipped(itemID, count)` 从 1 号槽起找空位：若测试先 `setEquipped(A,2)` 再
  `setEquipped(B,1)`，B 会落在槽 3。现有测试是否依赖具体槽位？该行为是否会制造脆弱断言？
- **E9** `CurrentCounts` 里 `all` 调用失败回落 `all = carried` 时 → `bank = 0`、`bags = carried − equipped`。
  该回落路径下各数是否仍自洽（不出现负数/怪值）？
- **E10** 删除 `SL.Tooltip` 后，仓库内（含 AGENTS.md、docs/、tools/）是否还有会误导的引用？
  （`docs/reports/` 里的历史审计报告提到 `SL.Tooltip._appliedScale` 属于已归档的复杂版，是否需要标注？）
